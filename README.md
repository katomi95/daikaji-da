# 大火事だ！

**遊べるURL：https://katomi95.github.io/daikaji-da/**（Meta Quest 3 のブラウザで開いてください。PCではプレビューモードで遊べます）

Meta Quest 3 のブラウザで遊ぶ、パススルーMRの消火ゲームです。「[火事だ！](https://katomi95.github.io/kaji-da/)」の続編です。

自分の部屋のあちこちでCGの炎が上がります。放っておいた炎は大きくなり、周りに燃え広がります。
右手の消火器で全部消せば「完全鎮火！」。延焼が止まらなくなると「もうだめだ！」。1プレイ1〜2分くらいです。

**どの火から消すか**がこのゲームの中心です。小さい火はすぐ消えますが、大きい火ほど燃え広がりやすく、消すのにも時間がかかります。

- WebXR Device API（`immersive-ar` セッション）+ Three.js r165
- HTML / CSS / JavaScript だけで動きます。ビルドもサーバー処理もありません。GitHub Pages にそのまま置けます
- Three.js は `vendor/` に同梱しています（CDNには依存しません）
- 効果音は WebAudio で合成しています（音声ファイルはありません）

## 遊び方

| | Quest 3 | PCプレビュー |
|---|---|---|
| 開始 | 「ゲーム開始」 | 「PCプレビューで遊ぶ」 |
| 見回す | 頭（体）を向ける | 画面をクリックしてマウスを動かす（Escで解除）／右ドラッグ／矢印キー・A D W S |
| 狙う | 右手コントローラーを炎に向ける | 画面中央の照準（○）を炎に合わせる |
| 噴射 | 右トリガーを押している間 | 左クリックを押している間 |
| 再スタート | 決着後にトリガー | 決着後にクリック |
| 終了 | Meta（Oculus）ボタン → 終了。タイトルに戻ります | 左上「タイトルへ戻る」 |

1. 開始して約1秒後、正面・左・右に炎が3つ出て「大火事だ！」と表示されます
2. 最初の8秒間は燃え広がりません。その間に状況を見て、消す順番を決めます
3. 炎は放っておくと大きくなり、火勢40を超えると近くに燃え広がり始めます。大きいほど広がるのが速くなります
4. 途中で、部屋のあちこちに新しい火が何か所かずつ出ます（全4回）。視界の外で出た火は「ボッ」という着火音の方向で分かります
5. 炎が全部消えて、新しい火ももう出ない状態になったら「完全鎮火！」。消火時間と消した炎の数が出ます
6. 炎が20か所になるか、全部の炎の勢いの合計が限界を超えると「もうだめだ！」

常に見える情報は、火元の数と経過時間だけです。Quest では消火器の頭に付いた小さな表示板に、PCでは画面上部に出ます。
移動しなくても遊べます。座ったままでも大丈夫です（左右に振り向く必要はあります。真後ろには火は出ません）。

## Quest 3 での起動方法

WebXR は **HTTPS** でしか動きません（`localhost` だけは例外です）。

### A. GitHub Pages で開く（おすすめ）

1. このフォルダ（`index.html` があるところ）をリポジトリのルートにして push します
2. GitHub のリポジトリで Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/(root)` にします
3. 少し待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けるようになります
4. Quest 3 の **Meta Quest ブラウザ** でこのURLを開き、「ゲーム開始」を押します
5. 許可のダイアログが出たら許可します。現実の部屋が見えたら開始です

周りに1.5〜3mほど物の少ない方向がある場所で、そちらを向いて開始すると遊びやすいです（炎は開始したときの正面を基準に、左右140°の範囲に出ます）。

### B. PC のローカルサーバーを USB 経由で Quest から開く（開発用）

1. PC でこのフォルダを配信します（`.js` を `text/javascript` で返すサーバーを使ってください。下の注意を参照）
   ```bash
   npx http-server -p 8000 -c-1
   ```
2. Quest を USB でつなぎ（開発者モードと adb が必要です）、ポートを転送します
   ```bash
   adb reverse tcp:8000 tcp:8000
   ```
3. Quest のブラウザで `http://localhost:8000/` を開きます（`localhost` は安全なコンテキスト扱いなので WebXR が使えます）

PCのIPアドレス（`http://192.168.x.x:8000`）で開くと HTTPS ではないので WebXR は使えません。タイトル画面にその理由が表示されます。

> 注意：Windows の `python -m http.server` は、レジストリの設定によっては `.js` を `text/plain` で返します。そうなると ES モジュールが読み込めず、画面が真っ暗になります。そのときは `npx http-server` などを使ってください。

## PCプレビューモード

1. 上と同じようにローカルサーバーで配信して、PCのブラウザ（Chrome / Edge / Firefox）で `http://localhost:8000/` を開きます
   - `index.html` をダブルクリックして `file://` で開いても動きません（ES モジュールの制約です）
2. 「PCプレビューで遊ぶ」を押します。仮想の部屋の椅子に座った目線になります
3. 画面をクリックするとマウスで見回せるようになります（ポインターロック。Esc で解除）
   - ポインターロックが使えない環境でも、**右ドラッグ**か**矢印キー / A D W S** で見回せます
4. 画面中央の照準（○）を炎に合わせて、**左クリックを押している間**噴射します

照準は常に画面中央なので、「マウスを動かす＝見回す」「左ボタン＝噴射」がぶつかりません。消火器のノズルは照準の先の炎に自動で向きます。

PCプレビューと Quest 版は、ゲームロジック（成長・延焼・消火・当たり判定・勝敗）・炎・消火器・文字表示をすべて共通で使っています。違うのは入力（マウスかコントローラーか）と背景（仮想の部屋かパススルーか）と、常時表示の出し方（画面上部か手元の板か）だけです。

## 難易度調整用パラメーター

すべて `js/logic.js` の先頭の `CONFIG` にまとめています。ロジックは Three.js にも DOM にも依存しないので、値を変えたら下の「バランスの確認」でシミュレーションできます。

| 値 | 初期値 | 意味 |
|---|---|---|
| `startDelay` | 1.0 | 開始ボタンから出火までの秒数 |
| `graceTime` | 8.0 | 出火から延焼が始まるまでの猶予（秒）。この間も炎は成長します |
| `retryDelay` | 1.5 | 決着後、再スタートを受け付けるまでの秒数（連打で即リスタートしないように） |
| `initialAngles` | 正面±12°・左55〜95°・右55〜95° | 最初の3つの炎の方向 |
| `initialIntensity` | 18, 30, 46 | 最初の3つの火勢（どこに割り当てるかは毎回シャッフル） |
| `initialDist` | 1.8〜2.5 m | 最初の炎までの距離 |
| `waves` | 15秒に2か所、30秒に3、46秒に3、62秒に4 | 新しく出火する時刻と数。全部出し切って全部消すとクリア |
| `waveWhenClear` | 2.0 | 炎が0になったら、次の波をこの秒数後に前倒しする（早く消すほど早く終わる） |
| `waveIntensity` | 12〜40 | 新しく出る火の火勢 |
| `growthMin` / `growthMax` | 1.7 / 2.9 | 成長速度（火勢/秒）。炎ごとにランダム |
| `growthAccelMin` | 0.6 | 小さい火の成長倍率。火勢50で1倍、100で1.4倍。大きい火ほど速く育ちます |
| `sprayResumeDelay` | 0.8 | 消火剤が外れてから再び成長し始めるまでの秒数 |
| `extinguishRate` | 16 | 当て続けたときに1秒で減る火勢。火勢30の小火≈1.9秒、60の中火≈3.8秒、100の大火≈6.3秒 |
| `spreadMin` | 40 | この火勢以上で延焼が始まる |
| `spreadCooldownMin` / `Max` | 6 / 10 | 延焼間隔（秒）。炎ごと・延焼ごとにランダム |
| `spreadTiers` | 90以上×0.5、70以上×0.72、40以上×1.0 | 火勢が高いほど延焼間隔が短くなる倍率 |
| `spreadDecay` | 0.5 | 火勢を40未満に下げたとき、延焼の溜まりが抜けていく速さ |
| `globalSpreadGap` | 1.2 | 部屋全体で、延焼と延焼の最短間隔（一斉発生を防ぐ） |
| `newFireIntensity` | 10〜18 | 延焼で生まれた火の火勢 |
| `spreadDist` | 0.8〜1.15 m | 延焼で生まれる火の、元の炎からの距離 |
| `minSeparation` | 0.75 m | 炎同士の最短距離（重ならない） |
| `minRadius` / `maxRadius` | 1.3 / 3.2 m | プレイヤーからの距離の範囲（近すぎず、消火剤が届く範囲） |
| `maxAngle` | 140° | 開始時の正面から左右何度まで炎を出すか（真後ろは避ける） |
| `loseCount` | 20 | 炎がこの数になったら「もうだめだ！」。同時に存在できる最大数でもあります |
| `loseTotal` | 900 | 全部の炎の火勢の合計がこれを超えたら「もうだめだ！」 |
| `sprayRange` | 5.0 m | 消火剤が届く距離 |
| `hitRadius0` / `hitSpread` | 0.16 / 0.09 | 当たり判定の半径（噴射口で0.16m、1m進むごとに+0.09m。さらに炎の幅の分だけ広がる） |

火勢と見た目の関係（`fireScale`）は同じファイルにあります。火勢1〜30が小火、31〜60が中火、61〜100が大火で、大きさ・揺れの激しさ・火の粉の量が変わります。

### 炎のデータ

ロジックの中の炎は次のような普通のオブジェクトです。

```js
{
  id: 1,
  position: { x: 0.3, y: 0, z: -2.2 }, // プレイ空間（開始時の足元が原点、正面が -Z）
  intensity: 46,          // 火勢 0〜100
  growthRate: 2.1,        // 成長速度（火勢/秒）
  spreadCooldown: 7.4,    // 延焼間隔の基準（秒）
  lastSpreadTime: 0,      // 最後に延焼した時刻
  spreadCharge: 0,        // 延焼までの溜まり（1で延焼）
  extinguishing: false,   // 消火剤を浴びているか
}
```

### 勝敗判定の順番

1フレームの中で「消火 → 成長 → 勝ち判定 → 新しい火の波 → 延焼 → 負け判定」の順に処理します（大きな dt は0.05秒ずつに分けて処理するので、フレームレートが変わっても速さは同じです）。

- 延焼は生きている炎からしか起こらず、遅れて出る火は「波」だけです。炎が0で波も残っていないときだけ勝ちになるので、勝った後に遅れて火が出ることはありません
- 最後の1つを消したのと同じフレームで、別の炎が延焼することはありません（炎が残っていれば勝ちにならないため）
- 決着したら、ロジックの更新（成長・延焼・消火）はすべて止まります。タイマー（setTimeout など）は使っていません

## バランスの確認（シミュレーション）

```bash
node tools/sim.mjs 400
```

本番と同じ `js/logic.js` を Node で動かして、いろいろな「消し方」の勝率を出します。プレイヤーは、首を振る速さに上限があり、狙いが合うまで少し時間がかかり、視界の外の火には少し遅れて気づく、というモデルです。初見の人を想定した遅めのプレイヤーは `SKILL=novice node tools/sim.mjs 400` で試せます（PowerShell では `$env:SKILL='novice'; node tools/sim.mjs 400`）。値を一時的に変えるときは `node tools/sim.mjs 300 '{"growthMax":3.2}'` のように JSON で渡せます。

いまの値での結果（400回ずつ）：

| 消し方 | 慣れた人 | 初見の人 |
|---|---|---|
| 何もしない | 0%（約35秒で負け） | 0% |
| 考えて消す（大きい火を優先し、あとは近い方向から） | 100% | 80% |
| 向いている方向から近い順 | 100% | 80% |
| 大きい火から | 100% | 69% |
| 自分から近い順 | 100% | 59% |
| 適当に選んで消し切る | 100% | 56% |
| 小さい火から | 100% | 42% |
| 慌てて適当（消し切る前に別の火へ移る・外しが多い） | 29% | 0% |

- 何もしなければ必ず負けます
- 落ち着いて1つずつ消し切れば勝てます。慣れた人ならクリアは1分くらいです
- 初見で慌てていると、消す順番で結果がはっきり変わります（小さい火ばかり追うと延焼が止まらない）
- 消し切る前にあちこち移ると、ほぼ確実に延焼に追いつかれます

シミュレーションのプレイヤーは機械的なモデルなので、実際の人の腕前とは違います。実機で遊んでみて、簡単すぎる・難しすぎるときは `growthMin/Max`・`extinguishRate`・`waves` あたりから調整してください。

## 「火事だ！」から引き継いだもの・変えたもの

そのまま流用：WebXR セッションの開始と終了、パススルー表示（背景透明）、床基準（`local-floor`／なければ頭から推定）、右手コントローラーの選び方とトリガー入力、振動、消火器の3Dモデル、消火剤と湯気のパーティクル、炎のシェーダ（見た目）、当たり判定の考え方（噴射の軸と炎の中心線の距離）、Canvas の文字パネル、警報音と噴射音。

変えたところ：

- 炎を1つから最大20に。1つずつメッシュを作るのではなく、全炎をインスタンス描画で3回の描画呼び出しにまとめました
- ロジックを `logic.js` に分けて、Three.js なしで動くようにしました（Node でシミュレーションできる）
- 炎は「プレイ空間」に置きます。出火の瞬間に、頭の位置（床）と顔の水平の向きに合わせて置きます
- 消火剤が複数の炎に同時にかかるときは、いちばん狙いの合っている1つだけが消えます（順番がゲームになるように）
- 着火音と消火音を PannerNode（HRTF）で火元の位置から鳴らします。火災全体の大きさに合わせて低い唸りが大きくなります
- PCプレビューで視点を動かせるようにしました（ポインターロック・右ドラッグ・キー）

## Quest Browser 向けの設計

- **セッション開始**：「ゲーム開始」ボタンのクリックの中で `navigator.xr.requestSession('immersive-ar', { optionalFeatures: ['local-floor'] })` を1回だけ呼びます。DOM Overlay・ヒットテスト・平面検出・アンカーなど、追加の許可が必要な機能は使っていません
- **対応チェック**：ページを開いたときに `isSessionSupported('immersive-ar')` を確認します。使えない場合はボタンを無効にして理由を表示します。VRセッションに切り替えることはしません
- **パススルー**：背景は `null`、クリアカラーはアルファ0、レンダラーは `alpha: true`
- **コントローラー**：`handedness === 'right'` のコントローラーに消火器を付けます。右手がないときは、つながっている方に付けます。トリガーは `selectstart` / `selectend` と `gamepad.buttons[0]` の両方を見ています
- **負荷**：炎は全部で描画呼び出し3回（外側の板・芯の板・床の照り返し）。ジオメトリとマテリアルは全炎で共有し、火勢などは1インスタンスごとの属性で渡します。粒子は 火の粉220・消火剤200・湯気120 の上限つきプールを使い回し、それぞれ1回の描画です。ライトは2つ、影はなし。消えた炎のデータは配列から外すだけで、GPU側のバッファは作り直しません
- **快適性**：文字は出たときの正面に固定して、頭について来ません。カメラシェイクや視点の強制移動はしません。「もうだめだ！」のときも画面は揺らしません。炎はゆっくり揺れるだけで、画面全体が明滅することはありません。炎は様式化したCGの見た目です

- 手元の表示板が見にくいときは、`js/main.js` の `statusPanel.position` / `rotation.x` を調整してください
- 床の高さがずれるときは、`local-floor` が使えているか確認してください（ガーディアン／境界の床の設定に影響されます）

## 既知の制約・今回実装していないもの

- Quest 3 の実機ではまだ確認していません（上の確認項目を参照してください）
- 現実の壁や家具は認識しません。炎はスタートしたときの頭の位置と向きを基準に置くので、家具や壁にめり込んで見えることがあります。CGの炎は現実の物の後ろに隠れません
- 消火器の残量・補充、スコア、ランキング、アイテム、プレイヤーの移動、煙の物理シミュレーション、オンライン機能はありません
- 視界の外の火元を示す矢印やマーカーはありません（音と見回しで探します）
- ハンドトラッキングには対応していません（コントローラーを使ってください）
- 明るい部屋では、炎が薄く見えることがあります（パススルーに半透明で重ねているためです）
